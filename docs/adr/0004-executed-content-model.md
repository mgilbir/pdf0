# 0004 — PDF/A rules apply to executed content, not present content

**Status:** accepted, in force.

## Context

A PDF carries resources that may never be drawn: a form XObject nobody invokes, a
colour space listed in `/Resources` that no operator selects, a font declared but
never used to show text. Applying font-embedding, colour and ExtGState rules to
everything *present* in the file is the obvious implementation and produces false
positives on conformant documents — the corpus rejects it (see
[ADR 0001](0001-corpus-as-oracle.md)).

## Decision

Rules about *used* resources are evaluated over content that is actually
executed. Validation walks page content streams and follows only what they
invoke — form XObjects drawn with `Do`, patterns painted with, shadings with
`sh`, the glyph procedures of the Type3 codes actually shown — and checks the
resources those paths reference. See `walkExecutedContent`, and for device
colour and font usage the content interpreter (`internal/core/interp.go`),
which executes content with a graphics state: an invoked form starts in its
caller's colour, font and render mode, and `Q` restores them.

Consequences that follow from the same principle, each corpus-confirmed:

- A form XObject that is never drawn triggers no font-embedding or colour rule.
- `q`/`Q` nesting depth is measured over executed content: a depth-30 form
  XObject that is never invoked does not breach the limit.
- Font rules apply to text actually shown; rendering modes 3 and 7 (invisible)
  are exempt from embedding and metric rules.
- Device-colour coverage counts a colour space only when an operator selects it
  — a selection counts even if nothing is painted with it (the corpus fails
  DeviceRGB set for stroking beside filled-only text) — or when painting uses a
  colour set earlier, inherited, or initial (DeviceGray).

## Consequences

- Rules cost more to write: the author must know whether the rule is about
  presence or use, and reach for the executed-content helpers when it is the
  latter. This is called out in the "adding a validation rule" checklist.
- It matches what veraPDF does, which is the point — the corpus is the oracle,
  and the corpus was generated by a checker that works this way.
- The walk is over untrusted input, so every recursion needs a visited-set and
  every index a bounds check. A content-stream walker is a DoS surface.
